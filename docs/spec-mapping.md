## 9.2 架构与 8.4 选型的取舍

| 规范建议 | 当前实现 | 理由 |
|---|---|---|
| LangGraph（interrupt + checkpoint）做人工闸门 | 数据库状态机（`charters.status`、`gate_approvals`、`outlines.gate_status`） | 闸门是长周期人工审批（天 / 周），用持久化状态机更简单可靠；后续如需多步智能体编排再引入 LangGraph |
| Arq / Celery + Redis 任务队列 | `jobs` 表数据库队列；单机进程内执行，服务器 / 云端独立 worker，PostgreSQL 用 `SKIP LOCKED` | 少一个依赖（Redis）；逐条入库、断点续跑 |
| LiteLLM 模型网关 | 自研 OpenAI 兼容适配层（规范列出的备选），可把 LiteLLM 作为一个提供方接入 | 路由、限额、计费、审计需要与项目权限和介入级别深度结合 |
| 混合检索 RAG（BM25 + 向量 + 重排）、LanceDB / pgvector、bge-m3 | ◐ 仅 BM25（`services/text.py`）；服务器版使用 pgvector 镜像，向量检索尚未接入 | 路线图 |
| ASReview 排序引擎 | 内置朴素贝叶斯主动学习排序 | 可替换；ASReview 项目导入导出尚未实现 |
| PaperQA2 证据问答 | ☐ | 路线图 |
| Docling / MinerU | ☐（GROBID 已接入） | 路线图；MinerU 因附加许可条款只做可选插件 |
| Tauri 桌面安装包 | ☐（单机版提供 Docker 与脚本两种方式） | 路线图 |
| Word 加载项（Office.js） | ☐ | 路线图 |
| 中英文界面 | ◐ 中文界面；中英文文献均支持 | 英文界面为路线图 |

## 验证情况

- 后端：14 个测试，包括用离线规则引擎走通 G0 → 检索 → 校准 → 辅助筛选 → 证据卡 → 学生先写大纲 → 证据地图 → G3 → 写作（审阅、L3 语言建议接受）→ 断言核查（修改后自动作废）→ AI 声明 → 导出 → 项目包导入的端到端测试，以及“数据不外发”、介入级别、权限、云端 API 调用（JSON 重试、计费、预算）测试。
- 前端：TypeScript 严格模式构建；来源标记算法单元测试；Playwright 在浏览器中走通主要页面。
- 部署：单机 Docker Compose（SQLite）与服务器 Docker Compose（PostgreSQL + SeaweedFS S3 + 独立 worker）均实际启动并通过冒烟测试。
- 外部接口（PubMed、Europe PMC、Crossref、OpenAlex、Zotero）的解析逻辑有单元测试；开发环境网络受限，未对真实接口做联调，首次部署时请用真实检索式验证。
